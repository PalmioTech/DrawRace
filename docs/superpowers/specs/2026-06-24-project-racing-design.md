# Project Racing — MVP Design Spec

**Status:** Approved (brainstorming)
**Date:** 2026-06-24
**Working name:** Project Racing (final name chosen at end of full GDD)
**Repo:** https://github.com/PalmioTech/DrawRace

---

## 1. Concept

A mobile-only, top-down arcade racer built on the "draw-to-race" idea: the player
does **not** drive the car directly. Before the race, the player traces a trajectory
on a closed circuit with their finger. The speed of the finger while drawing encodes
the throttle. When drawing ends, the car replays that trajectory and the player
watches the result, competing on time and positions.

Inspired conceptually by the draw-to-race genre but with original mechanics, art,
and content. No copied assets, names, tracks, or content from existing games.

## 2. Target & Constraints

- **Platform:** smartphone + tablet (iOS + Android), browser/WebGL. Touch-only.
- **Performance:** stable 60 FPS.
- **Orientation:** the whole track fits on one screen — fixed camera, no scrolling.
- **Stack:** Phaser 3 + TypeScript + Vite. Menus/HUD built inside Phaser (no React for MVP).

## 3. Core Mechanic — Draw-to-Race (finger-speed model)

The defining mechanic. The car's speed along the path is derived from **how fast the
player moved their finger** while drawing, not from curvature alone.

- While the finger moves, record points as `{ x, y, t }` (position + timestamp).
- **Throttle = finger speed**: `distance(p[i], p[i-1]) / (t[i] - t[i-1])`.
  - Fast finger on straights → fast car.
  - Slow finger into corners → slow car (the skill: ease off before tight turns).
- Raw input is smoothed with a **Catmull-Rom spline** and resampled to even spacing,
  so the trajectory is fluid even from rough touch input.

### Drawing flow

- The player draws **3 full laps** in one continuous stroke (the line loops the
  on-screen circuit 3 times). The race therefore lasts longer and rewards stamina/consistency.
- Each lap may take a slightly different racing line — the overlapping line is expected.
- A **lap counter** is shown live during drawing (start line crossed N times).
- **Validation:** the stroke must cross the start line 3 times (3 completed laps) and
  stay roughly within the track bounds. Invalid → prompt redraw.
- **Undo / redraw** available before confirming.
- Real-time line preview, colored by speed (e.g. green = fast, red = slow).

## 4. Race Flow

1. **Setup (MenuScene):** choose mode (*vs Computer* or *Hotseat local*) and number of
   opponents (1–3, so 2–4 cars total).
2. **Draw phase (DrawScene):** each human racer draws their 3-lap trajectory **in turn**
   on the same device. AI opponents generate their trajectory internally (no drawing).
3. **Race phase (RaceScene):** all cars start together and replay their own speed
   profiles for 3 laps. **No input during the race** — the player watches.
4. **Result (ResultScene):** final ranking, total time, win/lose. Save best time.

## 5. Physics / Simulation

Fixed-timestep simulation (60 Hz) with interpolated rendering for stable 60 FPS.

- A car follows its smoothed spline at the recorded speed profile, **capped by physics**:
  - **Max corner speed = f(curvature radius).** Tight curve + high recorded throttle → excess.
  - **Excess → grip loss:** the car slides outward, bleeds speed, takes a time penalty —
    but keeps going (arcade, forgiving; never a hard stop).
  - **Off track** (outside borders) → reduced grip surface + slowdown.
- **No car-to-car collisions.** Cars are "ghosts" to each other — each follows its own
  line with its own slips. Overtaking is **positional only** (progress/distance along
  track), no contact, no shoving.
- Ranking is computed from progress along the track (lap + distance into lap).

## 6. AI

- AI produces only a **trajectory** (points + speed profile); the same `CarSim` then runs
  it identically to a human's. The engine does not distinguish human vs AI sources.
- Trajectory generated by following the track's **ideal racing line** (precomputed or
  centerline waypoints with corner apex bias).
- **Difficulty** = how closely it hugs the ideal line + how much throttle it dares in corners.
- **Random errors:** occasionally overshoots throttle into a corner (slides), simulating
  a human mistake. Error frequency/magnitude scales inversely with difficulty.

## 7. Architecture

Phaser 3 + TypeScript + Vite. `core/` is pure TS logic (testable without Phaser);
`scenes/` handle only rendering + input.

```
project-racing/
├── index.html
├── package.json
├── vite.config.ts
├── tsconfig.json
├── public/
│   └── assets/            # car sprites, track textures, audio
├── src/
│   ├── main.ts            # bootstrap Phaser, responsive mobile config
│   ├── scenes/
│   │   ├── BootScene.ts       # preload assets
│   │   ├── MenuScene.ts       # mode select, opponent count
│   │   ├── DrawScene.ts       # draw phase (per racer, in turn)
│   │   ├── RaceScene.ts       # simulation + race rendering
│   │   └── ResultScene.ts     # ranking, best time
│   ├── core/
│   │   ├── Track.ts           # track geometry, borders, start line
│   │   ├── PathRecorder.ts    # record {x,y,t}, count laps
│   │   ├── PathSmoother.ts    # Catmull-Rom spline + resampling
│   │   ├── SpeedProfile.ts    # finger timing → speed profile
│   │   ├── CarSim.ts          # one car's physics: follow path, grip, slide
│   │   ├── RaceEngine.ts      # advance all cars, ranking, laps
│   │   └── AIDriver.ts        # generate AI trajectory + errors
│   ├── data/
│   │   ├── tracks.ts          # MVP track def (waypoints, borders)
│   │   └── SaveManager.ts     # localStorage: best times, settings
│   ├── ui/
│   │   └── Hud.ts             # laps, position, draw counter
│   └── config/
│       └── constants.ts       # physics tuning, neon colors
```

**Key separation:** `CarSim` does not know whether a trajectory came from a human draw
or AI — both are just arrays of points + speed. This keeps the two race-setup flows
(vs Computer / Hotseat) feeding a single shared simulation core.

## 8. Local Save (localStorage)

- `best_times` per track, `settings` (audio, difficulty), `unlocks` (empty in MVP).
- JSON serialized, versioned with `schemaVersion` for future migrations.

## 9. Visual Style

Top-down, modern **neon-futuristic** look. Minimalist UI, large touch-friendly buttons.
Light particle effects (trail, slide sparks). Smooth 60 FPS animation. Speed-colored
draw line as a core visual feedback element.

## 10. MVP Scope

**IN:** 1 track, modes vs Computer + Hotseat, 1–4 cars, 3-lap finger draw, grip/slide
physics, AI with difficulty + errors, live ranking, best-time save, base neon style.

**OUT (later phases):** campaign, tournaments, track editor, daily challenges,
skins/cosmetics, nitro/power-ups, 8 cars, multiple biomes (city/desert/futuristic),
race replay, advanced audio.

## 11. Roadmap (high level)

- **MVP** (this spec): one track, the core draw-to-race loop, vs AI + hotseat, save.
- **Beta:** progression/campaign, unlockable cars, more tracks/biomes, power-ups, replay.
- **Release:** cosmetics shop (no pay-to-win), tournaments, daily events, track editor,
  polish + audio, final name + branding.
